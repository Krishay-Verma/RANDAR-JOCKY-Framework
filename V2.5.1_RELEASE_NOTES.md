# RANDAR V2.5.1 — Investigation UI and capability integration hotfix

V2.5.1 fixes the investigation workflow so the V2.4 memory-forensics and V2.5 driver-forensics capabilities are visible and usable from stored investigations, not only from their standalone workspaces.

## Fixed

- Added dedicated **Memory Forensics** and **Driver Forensics** tabs to investigation details.
- Added memory/driver finding filters to the investigation findings workspace.
- Added memory/driver evidence summaries to the investigations list.
- Added lightweight server-side JSON projections so the list does not transmit full report bodies just to render forensics status.
- Fixed the existing investigation-list DLL/PE summary, which previously expected `report_json` in a paginated summary response where it was not present.
- Added Memory Forensics and Driver Forensics templates to New Investigation.
- Added `driver_inventory` to the Domain Expansion Triage template.
- Added the V2.5 memory/driver analysis rules to Domain Expansion Triage.
- Fixed the Engine Reference formatting: capability names and descriptions are now stacked, wrapped, aligned, and keyboard-focusable instead of running together.
- Added regression coverage for these UI/source integration paths.

## Scope

This release does not change the defensive memory/driver collection boundary. No kernel modification, vulnerable-driver exploitation, process injection, process hollowing, or security-control bypass functionality is added.
