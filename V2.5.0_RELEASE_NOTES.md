# RANDAR V2.5.1 — Driver / Kernel Forensics Research Track

V2.5 implements the roadmap's kernel/driver research track as a controlled,
read-only forensic capability.

## Included

- Windows driver inventory with registered/loaded state, service metadata,
  image path, SHA-256, best-effort signer/publisher/version metadata, and
  operator-supplied vulnerable-driver catalog correlation.
- New `/api/driver-forensics/scan` authenticated endpoint.
- Kernel/security observation report correlating driver evidence with available
  Windows Event Log and Sysmon telemetry.
- Deterministic forensic snapshot SHA-256.
- Explicit driver exposure findings with vulnerability provenance and analyst
  next checks.
- New Driver Forensics console page and CLI-compatible collector path.
- Regression tests for catalog provenance, load state, snapshot identity, and
  read-only kernel boundaries.

## Vulnerability intelligence boundary

RANDAR does not claim that a driver is vulnerable from a generic heuristic.
`known_vulnerable` and vulnerability IDs are derived from the configured
operator-supplied catalog (`RANDAR_VULNERABLE_DRIVER_DB`). Catalog freshness
and provenance are shown in the result.

## Kernel safety boundary

Production RANDAR does not load, unload, open, exploit, patch, disable
callbacks, modify kernel structures, or change security-control state. The
kernel observation layer records available telemetry and driver metadata only.
