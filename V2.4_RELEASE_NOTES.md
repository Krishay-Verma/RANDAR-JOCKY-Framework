# RANDAR V2.4.0 — In-Memory Runtime & Memory Forensics

V2.4 formalizes the in-memory JOCKY runtime identity and adds a read-only
memory-forensics workflow over Windows virtual-memory metadata.

## Implemented

- Explicit `in-memory-interpreter` runtime mode and V2.4 runtime identity.
- Read-only memory-forensics correlation service.
- Bounded collection of processes, modules, threads, and virtual-memory regions.
- Detection correlation for private executable memory and thread starts landing in
  private executable regions.
- Snapshot SHA-256 identity for normalized forensic metadata.
- New authenticated API: `POST /api/memory-forensics/scan`.
- New console page: **Memory Forensics**.
- Process-level correlation table and detection findings in the UI.
- Regression tests for deterministic snapshot identity and runtime versioning.

## Deliberate boundary

V2.4 does not read or write process-memory bytes, dump memory, inject code,
hollow processes, perform reflective loading, hijack threads, bypass endpoint
security, or alter kernel/process state. The memory-forensics workflow is
metadata-only and detection-focused.
