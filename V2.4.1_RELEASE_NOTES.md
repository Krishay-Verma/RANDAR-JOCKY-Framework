# RANDAR V2.4.1 — Memory Forensics Reliability & Reporting

V2.4.1 is a maintenance release on top of the verified V2.4.0 baseline.

## Fix

The Memory Forensics workspace could show correlated processes such as processes with writable/executable memory while the Detection Findings section remained empty. The API previously relied only on technique-specific rules, several of which intentionally require stronger multi-artifact combinations.

V2.4.1 now emits a conservative `memory_forensics_correlation` finding for every non-context process correlation. Thread-start correlations are represented with higher review severity; single writable/executable or multiple private-executable regions produce a review finding. These remain indicators and do not establish injection, hollowing, or reflective loading.

## Reliability improvements

- API returns `finding_count`.
- Collector/rule errors remain visible as `collector_errors`.
- UI renders explicit findings, empty states, and scan diagnostics.
- Regression tests cover the previously blank detection section.
- Duplicate startup import removed.

## Boundary

No process-memory bytes are read or written. No injection, hollowing, thread modification, security-control bypass, or kernel manipulation is introduced.
