# JOCKY V2.0 Toolchain

JOCKY V2.0 formalizes the existing RANDAR Forensics-as-Code language and adds a
cross-platform compiler/toolchain contract for Windows and Ubuntu.

## Pipeline

```text
JOCKY source
    |
    v
Lexer -> Parser -> typed IR
                  |
                  +--> canonical IR hash
                  |
                  v
             bytecode compiler
                  |
                  +--> source hash
                  +--> compiler/IR metadata
                  +--> target metadata
                  v
          signed JOCKY bytecode
```

The bytecode format remains backward-compatible with the existing V1 wire
format (`version = 1`). V2.0 is the **toolchain/language release**, not an
incompatible bytecode-wire release. Existing API consumers therefore continue
to work while new artifacts carry V2.0 metadata.

## Supported targets

- `portable` — platform-neutral JOCKY bytecode.
- `windows` — Windows endpoint/runtime target.
- `ubuntu` — Ubuntu/Linux endpoint/runtime target.

The language/compiler is platform-neutral. Platform-specific collection is
kept behind RANDAR's collector registry and interpreter rather than embedded
in the language grammar. Non-portable artifacts are checked by the runtime
before execution so a Windows artifact is not silently run on an Ubuntu host
or vice versa.

## CLI

```text
jocky compile <source.jocky> -o <output.jbc> [--target portable|windows|ubuntu]
jocky validate <source.jocky>
jocky verify <output.jbc>
jocky inspect <output.jbc>
jocky sign <source.jocky> -o <output.jbc>
jocky run <source.jocky>
jocky spec
```

`compile` and `sign` both produce signed bytecode. `sign` is provided as a
clear toolchain verb for CI/CD integrations; it does not bypass validation.

## Reproducible builds

Use `--deterministic`. The artifact then records a null build timestamp and
stable source/IR hashes. With the same source, compiler version, target and
signing key, the generated bytecode is byte-for-byte reproducible.

## Security invariants

1. Source is still lexed and parsed before compilation.
2. Bytecode is HMAC-signed and verified before execution.
3. Unknown collectors and analysis rules are rejected by semantic validation.
4. Target values are constrained to `portable`, `windows`, and `ubuntu`.
5. V2.0 adds metadata; it does not introduce arbitrary native execution into
   the JOCKY language.
