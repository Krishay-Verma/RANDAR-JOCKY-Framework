# RANDAR V2.8.0 — Forensic scan persistence, investigation integration & UI reliability

## Fixed
- Standalone Memory Forensics scans now create immutable RANDAR investigations.
- Standalone Driver Forensics scans now create immutable RANDAR investigations.
- Standalone Persistence & Privilege scans now create immutable RANDAR investigations.
- Investigation list/detail forensic projections now work for scans launched from the sidebar as well as JOCKY templates.
- Registered the existing `driver_forensics_exposure` rule in the live JOCKY analysis registry, fixing New Investigation validation for the Domain Expansion Triage template.
- Fixed the investigation summary resource strip where inline labels could visually run together (for example `Execution: completeElapsed: ...`).
- Added human-readable labels for V2.4–V2.6 forensic findings.

## Added
- Standalone forensic scan reports use the same immutable `Report` schema, integrity hash, audit event, evidence hashes and collector metadata as normal investigations.
- Sidebar forensic workspaces show the saved investigation ID and provide a direct pivot back into the relevant investigation tab.
- Standalone scans preserve scan type and snapshot hash in report provenance.
- V2.8 regression coverage for rule registration, template validation, standalone scan persistence UI and summary typography.

## Safety boundary
V2.8 remains read-only and evidence-oriented. It does not add driver exploitation, kernel modification, process injection/hollowing, security-control bypass, or arbitrary OS command execution.

### V2.8.1 maintenance note
Standalone forensic scans are decoupled from browser route lifetime. Memory, Driver, and Persistence scans run in bounded server-side background workers and are recoverable after navigation through session-persisted job IDs.
