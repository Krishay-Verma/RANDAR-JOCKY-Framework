# RANDAR V2.8.1 — Background forensic scan continuity

## Problem fixed

Standalone Memory, Driver, and Persistence scans were coupled to a browser page making the request. Leaving the forensic workspace could make the analyst lose the active scan UI and, depending on the client/server connection lifecycle, could make an in-flight operation appear to stop.

## Implementation

- Added a bounded server-side forensic job executor.
- Added authenticated job creation/status endpoints:
  - `POST /api/forensic-jobs/memory`
  - `POST /api/forensic-jobs/driver`
  - `POST /api/forensic-jobs/persistence`
  - `GET /api/forensic-jobs/{job_id}`
- Existing synchronous scan endpoints remain available for API automation compatibility.
- Memory, Driver, and Persistence pages now start background jobs instead of holding the page open on a long-running HTTP request.
- Active job IDs are kept in `sessionStorage`; reopening a workspace resumes status polling.
- Unmounting a page only stops its polling timer; it does not cancel the server-side scan.
- The server persists the normal RANDAR investigation before publishing the completed job result.
- Job state is bounded to prevent unbounded process-local memory growth.
