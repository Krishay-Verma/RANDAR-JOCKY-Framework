# RANDAR V2.3.0 — Runtime Representation & Execution Research

V2.3 adds the execution-abstraction and observability layer described by the
SIH-derived development direction. It routes validated JOCKY investigations
through an explicit named adapter and records structured runtime telemetry.

## Implemented

- Controlled `jocky-interpreter` execution adapter.
- Runtime identity and host/target metadata.
- Structured lifecycle/progress/completion events.
- Resource usage and forensic-artifact summaries.
- Bytecode API execution now returns runtime telemetry.
- Adapter and target validation.
- Regression tests for telemetry and adapter boundaries.

## Deliberate boundary

V2.3 does not provide arbitrary command execution, process injection,
process hollowing, reflective loading, API unhooking, direct system calls,
thread hijacking, kernel manipulation, or security-control bypass behavior.

Those behaviors are not required to make the execution abstraction and
observation layer functional.

## V2.3.1 hotfix

- Extended the Runtime page request timeout to 660 seconds so it can wait for
  the interpreter's bounded 600-second investigation limit instead of showing
  a client-side timeout at 60 seconds.
- Kept the normal API timeout at 60 seconds for other endpoints.
- Added explicit Runtime UI guidance that Windows process/memory collectors
  can take several minutes.
- Updated package/toolchain/runtime release identity to `2.3.1`.
